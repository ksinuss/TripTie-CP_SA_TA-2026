Анализ стейкхолдеров

Классификация стейкхолдеров​

Ключевые группы для функционала UC-02​

СтейкхолдерРольВзаимодействие
Пользователи (путешественники)Конечные потребители функционалаКонсультируются через опросы на этапе проектирования интерфейса. Их обратная связь критична для определения приоритетов параметров маршрута. Информируются о новых возможностях через обновления приложения.
Разработчики (Backend)Реализация логикиРеализуют алгоритм генерации маршрута, интеграцию с внешними API, обработку данных. Отвечают за техническую корректность. Информируются о результатах тестирования и обратной связи пользователей.
UI/UX-дизайнерПроектирование интерфейсаОтвечает за дизайн взаимодействия с функцией генерации маршрута. Консультируется с системным аналитиком по требованиям и с пользователями через юзабилити-тесты. Информирует команду о UX-решениях.
QA-инженерТестированиеОтвечает за тестирование функционала, выявление багов. Консультируется с разработчиками по спецификации, с аналитиком — по критериям приёмки. Информирует команду о результатах тестов.
ИнвесторыФинансированиеИнформируются о прогрессе разработки ключевых функций, влияющих на ценность продукта. Не участвуют в технических решениях, но могут влиять на приоритизацию.
Владельцы внешних APIПоставщики данныхКонсультируются при проектировании интеграции для соблюдения правил использования API. Информируются о масштабах использования их сервисов.
Системный аналитикСбор требованийКонсультируется по всем аспектам функционала для уточнения требований. Информирует команду о результатах анализа и собранных требованиях.

Вопросы для интервью со стейкхолдерами​

Для пользователей (путешественников)​

1. Критерии формирования маршрута​

Вопрос:
Какие критерии наиболее важны для вас при формировании маршрута для путешествия?

Варианты для уточнения:

  • Близость локаций от отеля
  • Общий километраж маршрута
  • Время посещения заведений
  • Бюджет
  • Смена видов деятельности
  • Наличие магазинов по пути

Цель:
Определить приоритеты для алгоритма генерации маршрута, понять, какие факторы должны иметь больший вес.

2. Оптимальное количество локаций​

Вопрос:
Какое количество локаций является по вашему мнению оптимальным для комфортного путешествия в один день?

Цель:
Уточнить бизнес-правило BR-02 (5–7 локаций в день), проверить соответствие реальным потребностям пользователей.

3. Уровень детализации информации​

Вопрос:
Какой уровень детализации информации о маршруте и каждой локации вы хотели бы видеть в сгенерированном маршруте?

Примеры данных:

  • Название и описание
  • Фотографии
  • Отзывы и рейтинг
  • Лучшее время посещения
  • Стоимость билетов/меню
  • Рекомендуемая одежда

Цель:
Определить объём информации для отображения в маршруте, подсчитать расход ресурсов для хранения и парсинга данных.

4. Формат визуализации маршрута​

Вопрос:
Как вы предпочитаете получать информацию о маршруте?

Варианты:

  • В виде списка по дням
  • На интерактивной карте
  • В календаре
  • Комбинация нескольких форматов

Цель:
Понять предпочтения пользователей по визуализации, приоритизировать сроки и уровень поддержки различных форматов.

5. Важность внешних данных​

Вопрос:
Какие внешние данные вы считаете наиболее важными для учёта при построении маршрута и выборе мероприятий?

Примеры:

  • Погода
  • Пробки
  • Время работы заведений
  • Лучший сезон для посещения
  • Популярность мероприятия
  • Отзывы
  • Бюджет
  • Внешняя привлекательность локации

Цель:
Определить приоритеты интеграции с внешними API, оптимизировать запросы.

6. Редактирование маршрута​

Вопрос:
Как вы представляете процесс редактирования сгенерированного маршрута? Какие изменения вы хотели бы иметь возможность вносить?

Цель:
Выявить требования к функционалу редактирования после генерации (открытый вопрос для брейншторминга).

7. Формат информации о завершённых поездках​

Вопрос:
В каком формате и объёме вы бы хотели видеть информацию о своих уже совершённых поездках?

Примеры данных:

  • Название, даты, маршрут
  • Краткое описание
  • Потраченный бюджет
  • Выбранные интересы
  • Общие впечатления и оценка
  • Общее количество пройденных километров / посещённых локаций

Цель:
Выявить ожидания по формату представления завершённых маршрутов, определить объём хранимой информации.

8. Уникальная функция​

Вопрос:
Если бы вы могли добавить одну функцию к заявленным на данный момент, что бы это было?

Цель:
Выявить скрытые потребности и возможности для уникальных функций (дифференциация от конкурентов).

Для разработчиков и аналитиков​

9. Реакция на непредвиденные изменения​

Вопрос:
Как система должна реагировать на непредвиденные изменения?

Примеры сценариев:

  • Закрытие музея в день поездки
  • Дождь во время запланированной прогулки
  • Изменение времени работы заведения

Цель:
Определить ожидания по адаптивности маршрута, требования к динамическому обновлению.

10. Учёт интересов нескольких участников​

Вопрос:
Как система должна учитывать разные интересы участников поездки при генерации маршрута?

Цель:
Определить механизм учёта предпочтений нескольких пользователей (алгоритм компромиссов, голосование, приоритеты).

11. Использование истории поездок​

Вопрос:
Как система должна использовать историю прошлых поездок пользователя для улучшения будущих рекомендаций?

Цель:
Определить стратегию сбора и хранения данных для улучшения рекомендаций (ML-модели, персонализация).
