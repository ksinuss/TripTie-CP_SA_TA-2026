# Процесс генерации маршрута по дням

## BPMN-диаграмма процесса

### Общая схема процесса

![BPMN: Генерация маршрута](/img/diagram_route-generation.png)

### Описание процесса

Процесс генерации маршрута состоит из следующих этапов:

#### Этап 1: Инициация процесса

- **Стартовое событие:** «Построить новый маршрут»
- **Действие пользователя:** Нажатие кнопки «Построить маршрут» в интерфейсе
- **Загрузка данных:** Система запрашивает параметры поездки из базы данных
- **Промежуточное событие:** «Параметры поездки загружены»

#### Этап 2: Параллельные запросы к внешним API

После загрузки параметров процесс разделяется на **три параллельных потока**:

| Поток | Задача | Внешний API | Возвращаемые данные |
|-------|--------|-------------|---------------------|
| **1** | Запросить данные из внешней системы погоды | API погоды (Open-Meteo / Яндекс.Погода) | Данные о погоде получены |
| **2** | Запросить данные из внешней системы карт | API карт (Яндекс.Карты / OSM) | Географические данные получены |
| **3** | Запросить данные из внешней системы мест | API мест (2GIS / TripAdvisor) | Данные о местах получены |

#### Этап 3: Синхронизация и обработка данных

- **Parallel Gateway:** «Все данные получены»
  - Процесс ждёт завершения **всех трёх** параллельных запросов
  - Только после получения всех данных процесс продолжается

- **Задача:** «Обработать полученные данные»
  - Валидация данных из разных источников
  - Нормализация форматов
  - Проверка согласованности

#### Этап 4: Применение бизнес-правил (DMN)

- **Business Rule Task:** «Применить правила генерации маршрута по DMN»
  - Вызов DMN-таблицы для определения количества локаций на день
  - Учёт факторов: количество участников, бюджет, предпочтения, погода
  
  → [Подробнее о DMN-решениях ↓](#2-dmn-таблица-бизнес-правил)

#### Этап 5: Валидация и корректировка

- **Exclusive Gateway (XOR):** «Маршрут сгенерирован корректно?»

**Вариант A: Нет (требуется корректировка)**
- Задача: «Выполнить корректировку маршрута»
- Возврат к применению бизнес-правил
- Цикл продолжается до получения корректного результата

**Вариант B: Да (маршрут корректен)**
- Задача: «Сохранить маршрут в БД»
- Промежуточное событие: «Маршрут успешно сгенерирован»

#### Этап 6: Отображение результата

- **Задача:** «Отобразить маршрут в интерфейсе»
  - Формирование списка локаций по дням
  - Отрисовка интерактивной карты
  - Отображение погодных условий

- **Конечное событие:** «Маршрут отображён»

## DMN-таблица бизнес-правил

### Общая информация

**ID решения:** `Decision_Locations-count`  
**Название:** «Определение количества локаций на день»

### Зачем используется DMN?

Использование DMN для принятия решений о количестве локаций в маршруте обосновано следующими факторами:

| Преимущество | Описание |
|--------------|----------|
| **Частое изменение бизнес-правил** | Правила генерации маршрутов будут корректироваться на основе обратной связи пользователей и аналитики. DMN позволяет изменять правила **без перекомпиляции кода**. |
| **Множество комбинаций факторов** | Решение зависит от **4 входных параметров** (участники, бюджет, предпочтения, погода). DMN-таблица делает их комбинации явными и тестируемыми. |
| **Прозрачность для бизнеса** | Бизнес-аналитики могут читать и понимать DMN-таблицы **без технических знаний**, что упрощает согласование правил с заказчиком. |
| **Масштабируемость** | При добавлении новых факторов достаточно добавить новые колонки в таблицу, **не меняя архитектуру системы**. |

### Входные параметры

| № | Параметр | Тип | Описание | Примеры значений |
|---|----------|-----|----------|------------------|
| 1 | **Количество участников** | number | Число участников поездки | `>= 3`, `< 3` |
| 2 | **Уровень бюджета** | string | Бюджет поездки на человека | `низкий`, `средний`, `высокий` |
| 3 | **Предпочтения группы** | string | Типы мест, интересные группе | `музеи, еда`, `развлечения, природа`, `любые` |
| 4 | **Погодные условия** | string | Прогноз погоды на день | `солнечно`, `пасмурно`, `дождь` |

### Выходной параметр

| Параметр | Тип | Описание | Диапазон значений |
|----------|-----|----------|-------------------|
| **Количество локаций на день** | number | Оптимальное количество точек для посещения в один день | `2–7` |

### Таблица решений

| Правило | Количество участников | Уровень бюджета | Предпочтения группы | Погодные условия | → Количество локаций |
|---------|----------------------|-----------------|---------------------|------------------|---------------------|
| **Rule 1** | `>= 3` | высокий | развлечения, природа | солнечно | **7** |
| **Rule 2** | `>= 3` | низкий | музеи, еда | пасмурно | **5** |
| **Rule 3** | `>= 3` | средний | любые | дождь | **2** |
| **Rule 4** | `< 3` | любой | развлечения, природа | солнечно | **5** |
| **Rule 5** | `>= 3` | средний | природа | пасмурно | **6** |

### Примеры применения правил

#### Пример 1: Большая компания с высоким бюджетом

**Входные данные:**
- Количество участников: 4 человека
- Уровень бюджета: высокий
- Предпочтения: развлечения, природа
- Погода: солнечно

**Применяемое правило:** Rule 1  
**Результат:** 7 локаций на день

**Обоснование:** Большая группа с высоким бюджетом может позволить себе насыщенную программу при хорошей погоде.

#### Пример 2: Дождливая погода

**Входные данные:**
- Количество участников: 5 человек
- Уровень бюджета: средний
- Предпочтения: любые
- Погода: дождь

**Применяемое правило:** Rule 3  
**Результат:** 2 локации на день

**Обоснование:** При дожде система приоритезирует крытые локации и сокращает количество перемещений.

#### Пример 3: Маленькая группа

**Входные данные:**
- Количество участников: 2 человека
- Уровень бюджета: любой
- Предпочтения: развлечения, природа
- Погода: солнечно

**Применяемое правило:** Rule 4  
**Результат:** 5 локаций на день

**Обоснование:** Маленькой группе проще перемещаться, но система предлагает умеренную нагрузку.

## Интеграция BPMN и DMN

### Как процесс взаимодействует с правилами

```
┌─────────────────────────────────────────────────────────────┐
│                     BPMN Process                            │
│                                                             │
│  [Запрос к API] → [Обработка данных] → [DMN Decision]      │
│                                           ↓                 │
│                     ┌─────────────────────────────┐        │
│                     │    DMN Engine               │        │
│                     │                             │        │
│                     │  Inputs:                    │        │
│                     │  - participants: 4          │        │
│                     │  - budget: "high"           │        │
│                     │  - preferences: [...]       │        │
│                     │  - weather: "sunny"         │        │
│                     │                             │        │
│                     │  Output:                    │        │
│                     │  - locations_count: 7       │        │
│                     └─────────────────────────────┘        │
│                                           ↓                 │
│                     [Генерация маршрута] → [Валидация]     │
└─────────────────────────────────────────────────────────────┘
```
