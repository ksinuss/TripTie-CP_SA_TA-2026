# Функциональные требования (Use Cases)

## UC-01: Создание новой поездки

| Поле | Значение |
|------|----------|
| **ID** | UC-01 |
| **Акторы** | Зарегистрированный пользователь (организатор) |
| **Предусловия** | Пользователь авторизован |

### Основной поток
1. Пользователь нажимает «Создать поездку».
2. Система показывает форму: город, даты, бюджет (опционально), предпочтения.
3. Пользователь заполняет обязательные поля (город, даты), выбирает предпочтения.
4. Система валидирует: даты в формате ДД.ММ.ГГГГ, начало ≤ конца, длительность ≤ 10 дней.
5. Система сохраняет поездку, присваивает UUID, перенаправляет на страницу поездки.

### Бизнес-правила
- `BR-01`: Название генерируется как «Поездка в [Город]».
- `BR-02`: Максимальная длительность — 10 дней.
- `BR-03`: Предпочтения по умолчанию: «развлечения» + «кафе».

### Альтернативные потоки
- **3.1**: Пользователь не выбрал предпочтения → система использует дефолтные.
- **4.1**: Ошибка валидации → подсветка полей, сообщение об ошибке.

## UC-02: Генерация маршрута по дням

| Поле | Значение |
|------|----------|
| **ID** | UC-02 |
| **Акторы** | Пользователь, система, внешние API |
| **Предусловия** | Поездка создана |

### Основной поток
1. Пользователь нажимает «Сгенерировать маршрут».
2. Система загружает параметры поездки из БД.
3. Система запрашивает у внешних API: прогноз погоды, список мест по предпочтениям.
4. Алгоритм группирует места по дням: учитывает расстояние, время работы, погоду.
5. Система отображает маршрут: список по дням + интерактивная карта.

### Бизнес-правила
- `BR-01`: Количество дней = длительности поездки.
- `BR-02`: Не более 5–7 локаций в день.
- `BR-03`: В дождь приоритет крытым местам.
- `BR-04`: Генерация только по запросу пользователя (не авто).

### Исключительные потоки
- **3.1**: Внешний API недоступен → используем кэш или пропускаем источник.
- **3.2**: Все API недоступны → сообщение «Попробуйте позже».

## UC-03: Приглашение участников

| Поле | Значение |
|------|----------|
| **ID** | UC-03 |
| **Акторы** | Организатор, приглашаемый пользователь |
| **Предусловия** | Поездка создана, организатор авторизован |

### Основной поток
1. Организатор нажимает «Пригласить».
2. Система генерирует уникальную ссылку и одноразовый код.
3. Организатор копирует и отправляет приглашение.
4. Приглашаемый переходит по ссылке или вводит код.
5. Система проверяет авторизацию: если нет — редирект на вход, затем авто-вступление.
6. Пользователь добавлен, список участников обновляется у всех.

### Бизнес-правила
- `BR-01`: Ссылка действительна до использования или конца поездки.
- `BR-02`: Один пользователь — один раз в одной поездке.
- `BR-03`: Код одноразовый, ссылка деактивируется после первого успешного использования.
