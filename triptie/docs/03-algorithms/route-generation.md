# Алгоритм генерации маршрута

## 🎯 Цель

Преобразовать параметры поездки (город, даты, предпочтения) в упорядоченный список локаций по дням, учитывая:
- географическую близость (минимизация перемещений),
- время работы заведений,
- погодные условия,
- баланс активностей (не только музеи или только кафе).

## 🧠 Подход: эвристики + правила (без ML на MVP)

```
Вход:
  - city, startDate, endDate
  - preferences: [museums, nature, ...], foodPreference
  - погода на каждый день (из API)

Шаг 1: Загрузка кандидатов
  → Запрос к 2GIS: места в городе, соответствующие предпочтениям
  → Фильтрация: только открытые в нужные даты, рейтинг ≥ 3.5

Шаг 2: Группировка по дням
  → Для каждого дня:
      • Выбрать 5–7 локаций
      • Учесть: расстояние между точками, время посещения, погоду

Шаг 3: Оптимизация порядка
  → Жадный алгоритм: начинать с ближайшей к отелю/предыдущей точке
  → Альтернатива: 2-opt для улучшения маршрута (опционально)

Шаг 4: Добавление перерывов и питания
  → Если день > 4 часов: вставить кафе рядом с локациями
  → Учесть foodPreference пользователя

Выход:
  → Структура: { day: 1, date: "...", locations: [ { placeId, timeslot, walkTime } ] }
```

## 🌧️ Учёт погоды

| Погода | Корректировка |
|--------|---------------|
| Дождь / снег | Приоритет крытым местам (музеи, ТЦ, кафе) |
| Жара > 25°C | Больше тенистых парков, меньше пеших переходов |
| Сильный ветер | Избегать открытых набережных, смотровых площадок |

## 📊 Оценка качества маршрута (для внутреннего логирования)

```python
def score_route(route: Route) -> float:
    score = 0
    # 1. Логистика: меньше перемещений = лучше
    score -= total_walk_time(route) * 0.1
    # 2. Разнообразие: баланс категорий
    score += diversity_bonus(route.categories)
    # 3. Погодное соответствие
    score += weather_match_score(route, weather_forecast)
    # 4. Рейтинг мест
    score += sum(place.rating for place in route.places) / len(route.places)
    return score
```

## 🔁 Перегенерация

Если пользователь редактирует маршрут вручную и запрашивает перегенерацию:
- Система сохраняет ручные правки как «фиксированные» локации
- Алгоритм заполняет оставшиеся слоты, не трогая зафиксированные точки
- Версия маршрута увеличивается, изменения синхронизируются через WebSocket
