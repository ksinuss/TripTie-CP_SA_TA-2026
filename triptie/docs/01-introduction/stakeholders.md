# Стейкхолдеры проекта

## Ключевые группы

| Стейкхолдер | Роль | Влияние |
|-------------|------|---------|
| **Пользователи** | Формируют требования к функционалу | Высокое — через обратную связь |
| **Инвесторы** | Определяют бюджет и сроки | Высокое — через приоритизацию |
| **Разработчики** | Оценивают техническую реализуемость | Среднее — через архитектурные решения |
| **Владельцы внешних API** | Предоставляют критичные данные | Среднее — через условия использования |

## Матрица ответственности (RACI)

| Задача | Команда | Инвесторы | Пользователи | Владельцы API |
|--------|---------|-----------|--------------|---------------|
| Определение концепции и требований | R | A | C | I |
| Выбор технологического стека | R | I | — | C |
| Приоритезация функций | R | A | C | — |
| Проектирование архитектуры | R | I | — | C |
| Разработка и тестирование | R | I | — | I |
| Релиз | R | A | I | I |
| Сбор обратной связи | R | A | C | — |

**Легенда**: R = Responsible, A = Accountable, C = Consulted, I = Informed
